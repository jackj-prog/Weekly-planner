## 1. What the app is for

**[I]** A personal routine executor for one user through a 30-week marathon block (29 Jun 2026 to 24 Jan 2027). It answers "what am I doing now, today, this week".

Behaviours the spec asks for (CLAUDE.md §4):
- opens on Now/Next;
- the run is the hero (distance, session, shoe, pace above the fold);
- two visual weights: quiet fixed life, full cards for variable work;
- ticks only on doable blocks;
- Today and Week as primary navigation;
- a live NOW;
- the countdown and the next key date always visible;
- a run can be logged and read back (pace, EF, decoupling, HR zones).

## 2. How the visual identity works (as implemented)

**[I/O]** Read in `css/style.css :root` and seen in screenshots.

- **Palette: near-black, grey, one red.**
  - Ground `#141414`, cards `#1f1f1f`, hairline `#333`, a white/grey text ladder.
  - One red, with two tokens: `--accent` for text, `--accent-fill` for fills.
- **Semantics:** red means hard (quality, race, key days, NOW); white means long; grey means easy and routine. Muted category tints appear only in emblems.
- **Type:**
  - Archivo 800/900 for display.
  - Space Mono for numbers and times.
  - Inter for instructions.
  - A system serif for the Book-of-Hours voice (italic labels, Roman numerals), never for data.
- **The art layer: a Book of Hours made of data.** Day clock, firmament, sun arcs, moons, sundial, vine, stained glass, seal, candles, wreath, tympanum. Rubrication red marks initials only; Latin is a light touch.
- **Motion:** token curves; arrivals run once; ambient loops are confined to art; all of it sits behind `prefers-reduced-motion`.
- **Enforcement:**
  - No hex colours outside `:root`, enforced by `tests/build.test.js`.
  - Token text pairs checked for WCAG AA.
  - No light theme.

# Pass 2 — functional (v5.10.2)

**Method.** Each journey was driven in headless Chromium at 390px with the real controls, with a fixture per scenario. After each action I read the same figures from Today, Week, the Kalendar, Plan and Reference. The scenario scripts are in the scratchpad under `fp/`; the regressions went into the repository.

## Journeys verified as consistent across views

These were already correct; no change.

- **Tick the day's run:** the Week heading, the Kalendar tally, the week line and the rays, and Plan's totals all move together.
- **Log a run (5.4 km, 33:00, HR 145):**
  - the recap shows the logged distance;
  - every total uses 5.4, not the planned 5;
  - the ledger shows pace 6:07 and EF 1.129, which matches (5400/33)/145.
- **Delete the log:** every view reverts, and the card returns to "Window ended".
- **Missed-run question:** "Ran as planned" ticks the run; "Didn't happen" skips it with the plan's note. Views agree.
- **Extra run on a rest day:**
  - Week shows "✓ 4 km unplanned";
  - the week total includes it;
  - Plan counts the run.
- **Navigation:**
  - the Today tab returns to today;
  - the Week tab returns to this week;
  - a day card or a Kalendar row opens its day;
  - weeks before and after the block render the standing week;
  - the Kalendar reopens on the current month.
- **Midnight with the app open on today:** it rolls to the next day and the countdown updates.

## Defects found and fixed

- **D1 — a run moved with "Move to…" was banked nowhere (high).**
  - *Reproduced:* Tuesday's 6 km run was moved to Friday and ticked there. The run card said "Completed", while the Week, the profile, the Kalendar and Plan all read 0 km.
  - *Cause:* every total ran `DB.recordedKm` on the plan-only day, which cannot see moves.
  - *The same cause also:*
    - stopped any week with a moved run from being sealed;
    - made Previously show the old day as missed and the new one as "+1 extra";
    - made the week-shape note call the slot short;
    - made the every-day grid show a miss and an extra;
    - dropped the run from its shoe's total.
  - *Fix:*
    - New `DB.recordedRuns(day, done, log, moves)`; `recordedKm` is its sum.
    - The optional `getMoves` argument is threaded through `weekKm`, `seasonShape` and `trainingJourney`.
    - The app has one resolver (`runMoves`, `recordedRunsOn`, `recordedOn`, `plannedRunRecorded`) used by every total: the ring, Week heading and bars, day cards, Previously, seal, guard, shape note, load note, journey, wall, Kalendar and shoes.
    - With no moves the result is identical (all prior checks unchanged).
- **D2 — the Week's distance profile left unplanned and moved-in runs out (low).** It now draws them; the day the run left reads "off", not "missed".
- **D3 — returning on a new day showed the page the phone was put away on (§4.1).** A return on a new day now opens that day's Today. A day that turns while the app is open still moves nothing.
- **F8 — the minute tick drifted from the real minute by up to 59 s.** It is now scheduled on the minute boundary.
- **F5 — the service worker precache could take stale files from the HTTP cache.** It now uses `cache: 'reload'`.
- **F9 — refused saves were silent, and storage persistence was never requested.**
  - `writeJSON` reports a refused save through a `.store-warn` alert.
  - `navigator.storage.persist()` is requested once.
